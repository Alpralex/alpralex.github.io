Como os dados circulam

O que construí

  1. Ingestão que só lê o que é novo

    Um pipeline Lakeflow usa o Auto Loader para recolher os ficheiros anuais de um volume do Unity Catalog. Quando chega um ficheiro novo, só esse é lido. A camada bronze guarda todas as colunas como texto, por isso uma data ou um valor mal formatado nunca interrompe o carregamento.

  2. Limpeza com regras de qualidade medidas

    A camada silver remove duplicados e define o tipo de cada coluna em PySpark. As linhas que violam uma regra obrigatória (sem identificador, sem data) vão para uma tabela de rejeitados com o nome da regra. As regras mais brandas só contam as falhas, e assim a qualidade da fonte fica visível em cada execução.

  3. Regras de negócio em dbt

    O dbt-databricks constrói a camada gold: seis dimensões, uma tabela de factos de contratos, uma ponte contrato–fornecedor e os marts por trás de cada gráfico. Correm 17 testes em cada atualização, incluindo um que compara os totais com a versão original em DuckDB.

  4. Privacidade desde a origem

    Os fornecedores que são pessoas singulares são mascarados antes da camada gold, e o Genie só vê gold. Quando se pergunta pelos maiores fornecedores, a resposta só indica empresas.

  5. Um deploy, um agendamento

    Um Databricks Asset Bundle publica os esquemas, o pipeline, o job semanal e o painel com um só comando. O código PySpark tem 13 testes unitários que correm no GitHub Actions sem precisar de workspace.

Dois erros que a migração apanhou

  • Um carregador transformou o "\b" das minhas expressões regulares num carácter de retrocesso. Todos os municípios caíram em silêncio na categoria "Outros", e os totais continuavam a bater certo. Agora há um teste que falha se isso voltar a acontecer.
  • O Spark arredonda as divisões de decimais a seis casas, o que alterava um índice de concentração de mercado de 59,0 para 58,3. As quotas passaram a ser calculadas em vírgula flutuante.
