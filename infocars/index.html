InfoCars

Used-car pricing for dealers · 2025

Dealers in Brazil price used cars by browsing a few listing sites. InfoCars answered two questions from the whole market instead: what a car should sell for, and which cars in stock are priced out of line. I designed and built it end to end at Informar Dados, and sold it to a car dealer.

Pipeline

How it works

  1. Match each ad to a catalogue

    Sellers write the same car in many ways: "Onix 1.0 LT", "GM ONIX LT 22/23", "onix lt flex". The matcher cleans the text, matches aliases on whole words so that "LT" never matches "LTZ", reads the model year from "22/23", and falls back to fuzzy matching for typos such as "Corola". In production this corrected 26,071 ads.

  2. Drop bad prices

    An ad is dropped when its price is missing, out of range, or far from comparable cars. The most common error is a price typed without its last digit. It still looks like a plausible car price, so only a comparison with similar cars catches it.

  3. Build market statistics

    For each version, year and state: median asking price, 25th and 75th percentiles, and median days on the site. An ad that disappears counts as sold on its last day online. In production these were materialised views in PostgreSQL.

  4. Answer the dealer

    Dashboards show what similar cars sell for, where a car sits against the market and which stock is priced out of line. The assistant answers the same questions in plain language.

Comparing the dealer's own figures before and after adoption, the saving was about R$2,000 (roughly €300) per vehicle negotiation, and time in stock came down to one to three months.

Pricing assistant

The assistant went through three designs. Each was tested on the same set of questions before the next one replaced it.

Version 1

Function calling

OpenAI and Grok models call predefined functions to fetch data.

Version 2

SQL agent

The model writes SQL against the modelled tables, reading only from an approved list.

Version 3

Claude with tool use

Three tools: market_price, price_position and a guarded run_sql. Model-written SQL is checked before it runs: one SELECT only, approved tables only, and a row limit. It also runs under a read-only database role. The system prompt and tool definitions are cached to cut cost and latency.

Run the demo

The repository is a sample rebuilt for this portfolio, with 1,200 synthetic listings. It does not contain the production code, real listings or the scraper. The demo runs on SQLite; the PostgreSQL schema, market views, quality checks and read-only role are in sql/postgres/.

cd infocars-pricing-showcase
pip install -r requirements.txt

pytest                     # 33 tests
