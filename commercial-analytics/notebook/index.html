How the commercial app was built, step by step¶

The business question. A sales director at a Portuguese animal-health distributor wants to know where the company is losing revenue, margin and cash, and what to do this week. The app answers five questions:

  1. Which region is falling, and why?
  2. Who gives margin away?
  3. Which customers should we call this week?
  4. Where is the cash stuck?
  5. What is seasonal?

How this notebook is organised. It follows the project in the order it was built:

Step What Tool
1 Generate a realistic data set with documented business rules Python (NumPy)
2 Load and check the raw files pandas
3 Model a star schema with tests dbt on DuckDB
4 Answer the five questions, with interactive charts pandas + Altair
5 Reconcile pandas with the dbt marts pandas + DuckDB
6 Publish: web dashboard, Power BI and Qlik JSON export, PBIP, Qlik script

The data are synthetic: a generator with a fixed seed writes 1,800 customers, 12 reps and about 951,000 order lines from January 2024 to September 2026. The rules it follows are listed in step 1, so the reader can check that the analysis finds them from the data alone.

The charts are interactive: hover for values, click a bar, a point or a legend entry to filter the linked chart. They are built with Altair. GitHub shows notebooks without JavaScript, so open the interactive version to use them.

Run it: pip install pandas numpy altair duckdb dbt-duckdb, then from the repository root python generator/generate.py and dbt build --profiles-dir ., and run all cells (about 1 minute).

Step 1. Generate the data¶

Real customer data from a distributor cannot be published, so the project starts from a generator (generator/generate.py) that writes CSV files with business behaviour planted on purpose. The rules, from the generator's docstring:

Rule Behaviour Question it tests
R1 Customers order more often in the weeks after a rep visit 3
R2 Customers with no visit for 60+ days start to lapse 3
R3 The South (Sul) lost a rep in January 2026; its customers are visited half as often 1
R4 Rep REP07 discounts about 9 points more than the others, with no volume gain 2
R5 Livestock farms pay late; about 7% of their invoices slip 90–200 days 4
R6 Vaccines peak in spring, parasiticides in summer, pet food is flat 5

The fixed seed (20261024) makes every run identical, so the numbers in this notebook, the dbt tests and the dashboards all agree. Generating takes about 40 seconds.

Step 2. Load and check the raw files¶

The files are normalised the way an ERP export would be: orders and order lines are separate, product category lives in the product table, and payments are a separate file keyed by invoice. Before modelling, three checks that catch most export problems: keys are unique, every foreign key resolves, and the dates sit inside the period.

Step 3. Model a star schema in dbt¶

The SQL lives in models/. Staging views type and rename the CSV columns; the marts form a star schema plus one or two marts per question:

  • Facts: fct_sales_lines (order-line grain, gross / net / cost amounts), fct_visits, fct_invoices (one row per invoice with its payment and aging bucket on the snapshot date).
  • Dimensions: dim_customer (with recency flags on the snapshot date), dim_product, dim_rep, dim_date (with year-to-date and last-12-months flags relative to the snapshot).
  • Question marts: mart_region_ytd, mart_rep_pricing, mart_call_list, mart_receivables_aging, mart_payment_by_segment, mart_category_seasons and others.

dbt build --profiles-dir . runs the models and the tests together: unique and not-null keys, relationships between facts and dimensions, accepted values for segments and buckets, and checks that the marts add up to the facts. On this data: 87 nodes, 0 failures. The model writes data/commercial.duckdb, which step 5 reads.

def yoy(frame, value, date_col):
    cur = frame[frame[date_col].between("2026-01-01", AS_OF)].groupby("region")[value].sum()
    prev = frame[frame[date_col].between("2025-01-01", "2025-09-30")].groupby("region")[value].sum()
    return cur, prev

Q3. Which customers should we call this week?¶

Two facts drive the call list. First, customers order more often in the weeks after a visit (R1). The chart below measures it from the data: for every customer-week, the share of weeks with an order, by weeks since the last visit.

In [9]:
# Weekly panel: did the customer order in the week, and how many weeks since their last visit?
wk = lambda s: s.dt.to_period("W-SUN").dt.start_time
ow = orders.assign(week=wk(orders["order_date"]))[["customer_id", "week"]].drop_duplicates().assign(ordered=1)
vw = visits.assign(week=wk(visits["visit_date"]))[["customer_id", "week"]].drop_duplicates()
weeks = pd.date_range("2024-03-04", "2026-09-21", freq="W-MON")
panel = pd.MultiIndex.from_product([customers["customer_id"], weeks], names=["customer_id", "week"]).to_frame(index=False)
panel = pd.merge_asof(panel.sort_values("week"), vw.rename(columns={"week": "last_visit"}).sort_values("last_visit"),
                      left_on="week", right_on="last_visit", by="customer_id", direction="backward")
panel["weeks_since_visit"] = ((panel["week"] - panel["last_visit"]).dt.days // 7).clip(upper=16)
panel = panel.merge(ow, on=["customer_id", "week"], how="left").fillna({"ordered": 0})
rate = panel.dropna(subset=["weeks_since_visit"]).groupby("weeks_since_visit")["ordered"].mean().reset_index()

alt.Chart(rate).mark_line(point=True, color=BLUE).encode(

Step 6. Publish¶

The same model is shown three ways, each where a recruiter or a user would meet it:

  • Web dashboard (web/, live at guilhermerigonato.com/commercial-analytics): scripts/export.py writes small JSON files from the marts, and plain JavaScript draws SVG charts. Clicking a region, rep, category, segment or recency band filters the other panels.
  • Power BI (powerbi/): a PBIP project on the same star schema, with DAX measures, row-level security by region and a Best Practice Analyzer check in bpa-rules.json.
  • Qlik Sense (qlik/): the load script builds the same model; the associative engine gives cross-filtering for free.

Which library for interactive charts¶

Library Linked charts Output Best for
Altair (Vega-Lite), used here Built in: selections shared across charts Static HTML, no server Reports and explorations that must open anywhere
Plotly Per chart; linking across charts needs Dash HTML; a Dash app for linking Rich single charts, maps
Bokeh Linked brushing through a shared data source HTML, or a Bokeh server Large scatter plots, custom tools
HoloViews + Panel link_selections in one call Notebook or Panel app Turning a notebook into a small app
Dash / Streamlit Any, through Python callbacks Needs a server Internal tools with live data
